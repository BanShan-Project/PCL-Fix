# 下载功能恢复版使用说明

**要直接使用，请优先下载 Actions 中的“官方 2.99 精确恢复版”。** 它在官方 2.99.0.0 程序上恢复下载入口，并关闭启动器云控与自更新，保留原程序的登录和下载鉴权实现。

本仓库是 [Meloong-Git/PCL](https://github.com/Meloong-Git/PCL) 的修改分支。修改及构建脚本可以查看；构建产物由本仓库的 GitHub Actions 生成。

## 两种产物有什么区别

| 项目 | 官方 2.99 精确恢复版（推荐直接使用） | Snapshot 源码恢复版 |
|---|---|---|
| 生成方式 | 对指定官方 EXE 的托管代码进行精确修改 | 从本仓库公开源码编译 |
| 下载恢复 | 修复游戏版本列表、整合包导入和安装、相关页面入口 | 关闭 `RestrictMcDownload`，编译源码中保留的正常下载逻辑 |
| 微软登录与 CurseForge | 保留原 EXE 中已有实现及配置 | 需配置自己的微软应用 Client ID 和 CurseForge API Key |
| 原版私有实现 | 保留与本次修改无关的代码，包括原有鉴权逻辑 | 上游未公开的代码不会因重新编译而自动补全 |
| 云控与启动器更新 | 关闭远端配置、缓存公告执行和自更新路径 | 使用本地配置初始化，关闭更新与替换路径 |
| 适合用途 | 现成运行包，尽量延续原版兼容性 | 阅读、修改源码和自行维护构建 |

“精确恢复”表示补丁针对校验过的特定二进制文件。它不是公开源码重新编译出的官方 Release，也不表示已在所有电脑和网络环境下完成测试。

## 下载和运行

1. 打开 [本仓库 Actions](https://github.com/TIMENEXSakura/PCL/actions)，进入成功完成的恢复构建。
2. 在该次运行的 **Artifacts** 下载精确恢复版压缩包；需要源码编译结果时再选 Snapshot。GitHub 可能要求登录后下载构建产物。
3. 完整解压，退出正在运行的 PCL，再运行解压后的恢复版 EXE。首次确认时建议保留原版文件，以便比较。

这是 Windows 桌面程序，目标框架是 .NET Framework 4.8。Android 下载目录只是文件存放位置，不能让 EXE 成为 Android 应用。

请以该次 Actions 的提交、构建日志及补丁报告识别产物。官方原包 `最新正式版.zip` 仍是补丁输入，**它本身不是恢复版**。

## 关闭了哪些云控和更新路径

修复范围包括：

- 不获取或执行 PCL 服务器的 `notice.cfg`、`ServerConfig.json`、`notice.json`，也不重放已有公告缓存。
- 不执行云端公告中的修改设置、结束程序、普通更新和静默更新动作。
- 关闭启动器更新下载、安装、退出时应用更新，以及 `--update` 替换 EXE 的路径。
- “检查更新”按钮改为说明本恢复版已关闭启动器更新。
- 整合包导出使用当前恢复版的本地副本，不再下载官方最新启动器或复用原版 `Latest.exe` 缓存。

因此，不需要靠反复删除云控缓存来维持修复。历史缓存文件即使存在，也不会再进入上述执行路径。之前已经保存的个人设置仍然保留；如果下载页被本地“功能隐藏”设置隐藏，需要在设置中重新显示。

Minecraft 版本元数据、游戏文件、Modrinth、CurseForge、Java 下载及账户登录仍按各自功能联网。这里关闭的是启动器远端配置和自更新，不是全部网络访问。内置 EasyTier 联机依赖上游云端配置，本次没有恢复该功能；2.99 原有的联机隐藏状态保留。

恢复版不会自动升级。以后更新本分支时，需手动下载新的恢复版替换程序；直接换回官方 EXE 会重新带回官方版本中的限制和云控代码。

## 自行构建 Snapshot 的凭据配置

公开源码没有提供原版的完整私有配置。Snapshot 为以下值保留了入口：

| 功能 | 运行时环境变量 | 可选 GitHub Actions 仓库 Secret |
|---|---|---|
| 微软账户登录 | `PCL_MS_CLIENT_ID` | `CLIENT_ID` |
| CurseForge API | `PCL_CURSEFORGE_API_KEY` | `CURSEFORGE_API_KEY` |

运行时环境变量优先；未设置时可使用构建时注入的值。都未配置时，对应功能可能失败；其他下载来源的可用性取决于各自服务。微软 Client ID 是自己的应用注册标识，不是账户密码，也不是 OAuth client secret。仅配置这两项也不等于补全上游所有未公开的 CDN 鉴权代码。

本机运行的 PowerShell 示例：

```powershell
$env:PCL_MS_CLIENT_ID = "你的微软应用 Client ID"
$env:PCL_CURSEFORGE_API_KEY = "你的 CurseForge API Key"
& ".\Plain Craft Launcher 2.exe"
```

若采用仓库 Secret，在仓库 **Settings → Secrets and variables → Actions** 添加表中名称后重新构建。注入二进制的值会随构建产物分发；仅供自己使用的 API Key 优先通过运行时环境变量提供。直接使用精确恢复版无需为了本次修复另行配置这两项。

## 精确恢复版如何复现

恢复流程使用上游仓库已有的官方 `最新正式版.zip`，不需要上传个人 EXE。当前基准是官方 2.99.0.0，其 EXE 与本次提供的样本 SHA-256 一致：

```text
6b6e1260cb5a1d6a303855f1c60cab3d0bc1aebba7e40a964180188b271e7386
```

需要恢复的方法以此前官方 2.14 版本作为对照，供体来源固定在上游提交 `5ef81e4`，并在执行修改前校验输入哈希。修改只针对已识别的方法与分支，保留新版其余实现。补丁脚本和输出报告用于说明具体改了哪些方法；不匹配的输入应停止处理，不能直接套用到其他版本。

## 验证范围

Actions 成功表示对应构建或补丁生成步骤及其检查通过。静态检查可以确认方法替换、分支目标、异常处理边界、输入哈希与输出结构，但不能代替 Windows 上的完整交互测试。

构建还会让 CLR 逐个编译所有改动过的方法（`tools/verification/jitcheck.ps1`），而不是只看 ILVerify 的结论：ILVerify 只做验证，不检查方法头的栈上限，也不检查"try 块不得落入处理器"这类导入器规则，因此存在“验证通过、一调用就 `InvalidProgramException`”的方法。2.99 恢复版的整合包安装入口曾经就是这种缺陷（try 块尾部被改成 nop 后顺序落入 finally），现已修复。

目前不能据此宣称已经完整验证微软登录、各种游戏版本下载、所有整合包格式、实际启动和长期运行。请结合该次运行日志判断执行了哪些检查；真实网络服务的响应也可能随时间变化。出现问题时，记录产物对应的提交、操作步骤和日志，有助于区分构建问题、下载源问题与本次恢复代码的问题。
